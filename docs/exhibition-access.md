# 학술제 QR 진입

## 방문객 화면

`/exhibition` → `/exhibition/signup` → `/exhibition/login` → `/home`

- 온보딩의 시작하기 버튼에서 회원가입 화면으로 이동한다.
- 이름 방문객, 학번 20260000, 이메일 visitor@unibus.example을 미리 채운다.
- 비밀번호는 화면 표시용 값이며 로그인 요청에 보내지 않는다. 모든 입력은 읽기 전용이다.
- 회원가입 버튼은 화면만 전환하며 가입 API를 호출하지 않는다.
- 로그인 버튼은 Spring의 `POST /auth/exhibition`을 호출한다.
- 방문객 안내 배너나 별도 설명은 추가하지 않는다.
- `/signup`, `/login`, `/admin/login`은 기존 직접 입력 방식을 유지한다.

## 기존 포스터 QR 적용

포스터 QR이 사이트 루트 `/`를 가리키는 경우 아래 설정 후 배포한다. QR 이미지를 바꿀 필요가 없다.

1. AWS 백엔드에 `UNIBUS_EXHIBITION_ENABLED=true` 설정 후 새 이미지를 배포한다.
2. Vercel에 `VITE_EXHIBITION_MODE=true` 설정 후 프런트를 새로 빌드·배포한다.
3. `VITE_AUTH_API_BASE_URL`은 새 Spring 백엔드를 가리켜야 한다. 기존 Edge에는 이 API가 없다.
4. 새 브라우저에서 `/` → 온보딩 → 가입 → 로그인 → 홈, 그리고 `/admin/login`을 확인한다.

프런트 설정이 false여도 `/exhibition`으로 직접 접근할 수 있으나, 백엔드 설정이 false이면 방문객 세션은 발급되지 않는다. 일반 백엔드는 기본 false이며, 학술제 배포 대상인 staging 프로필과 staging Compose는 기본 true다. 프런트 production 빌드는 `.env.production`에서 true를 읽는다. 플랫폼에 명시한 환경변수 값이 있으면 그 값을 우선한다. 행사 종료 시 두 값을 false로 설정하고 프런트를 다시 빌드한다.

## 세션과 데이터

- 서버는 예약된 UUID `e0000000-0000-4000-8000-000000000026`의 일반 사용자 계정을 최초 로그인 때 한 번 준비한다. 방문객마다 계정을 만들지 않는다.
- 이 계정에는 비밀번호가 없고 일반 회원가입으로 같은 이메일을 사용할 수 없다.
- 방문객마다 독립적인 토큰을 발급하며 유효기간은 4시간이다. 한 방문객의 로그아웃은 다른 토큰을 삭제하지 않는다.
- 문의 작성과 푸시 구독 변경을 차단한다. 노선·정류장·공지 조회는 기존 공개 API를 이용한다.
- 관리자·기사 API는 기존 서버 권한 검사를 유지한다. 예약 계정의 역할·이메일·비밀번호가 바뀌면 방문객 인증을 거부한다.
- 방문객 기능을 끄면 기존 방문객 토큰도 인증에 사용할 수 없다. 기존 계정·노선·정류장·공지 데이터를 덮어쓰지 않는다.

## 검증

- `ExhibitionServiceTest`: 비활성화, 독립 세션, 관리자·기사 역할 거부, 만료와 비활성화 후 인증 거부, 문의·푸시 쓰기 차단.
- 로컬 UI fixture: 루트 온보딩, 읽기 전용 가입·로그인, 홈 이동, 일반 입력 화면 및 관리자 접근 분리.
- 실제 AWS·Supabase 환경에서의 신규 세션 발급은 배포 후 확인해야 한다.
