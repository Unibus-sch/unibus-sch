# UNIBUS UI 디자인 검토

검토일: 2026-10-06 (한국 시간)
브랜치: `codex/pwa-ui-optimization` / `1002c47`
범위: 사용자 모바일 앱. 디자인 구현은 변경하지 않고 검토 결과만 기록했다.

## 검토 방법과 한계

- 로컬 Vite와 기존 `scripts/ui-fixture-server.mjs`를 실행해 실제 UI를 확인했다.
- 390×844에서 로그인·홈·공지·설정, 다크 모드의 홈·설정·통학 빈 상태·셔틀 패널을 확인했다.
- 320×568에서 홈 초기/스크롤 상태와 온보딩을 확인했다.
- 공지는 로컬 테스트 공지 25개다. 제목 길이와 색상 빈도는 운영 데이터와 다를 수 있다.
- 통학 노선 데이터는 비어 있다. 노선 카드의 실제 렌더링은 검증하지 않았고 관련 의견은 소스 검토로 구분한다.
- 실제 지도 SDK·위치 권한·iPhone 설치형 PWA·키보드는 검증하지 않았다. 로컬 환경에서 지도가 비어 보이는 현상은 디자인 결함으로 판정하지 않았다.
- 아래 크기·색상·굵기는 코드/화면에서 확인한 사실이다. 제안하는 디자인 값과 우선순위는 검토자의 판단이다.

## 전체 판단

남색을 중심으로 한 브랜드와 화면 구조는 이미 형성되어 있다. 완성도를 낮추는 주요 원인은 작은 보조 글씨, 과도하게 넓은 굵은 글씨 사용, 같은 성격의 컨트롤에 서로 다른 시각 규칙을 적용하는 것이다. 우선 글씨와 대비를 정리한 뒤 정보 위계·카드·버튼을 통일하는 편이 효과적이다.

## 먼저 해결할 문제

### 1. 보조 글씨가 너무 작다 — 높음

홈 전철 안내 10px, 도착까지 남은 시간 11px, 목적지 12px, 급행 배지 8px, 하단 메뉴 10px이다. 셔틀 안내와 지도 라벨에도 9~12px 글씨가 있다. 이동하면서 확인할 버스 앱에서 핵심 정보 주변의 작은 글씨가 읽기 어렵다. 굵기를 올려도 글자 자체가 커지지는 않는다.

제안: 본문 15~16px, 보조 정보 13px, 배지·메뉴 12px를 기본으로 삼는다. 시간·도착까지 남은 분은 별도 강조하고, 글씨 확대에 맞춰 줄 높이와 카드 높이도 함께 조정한다.

근거: `src/app/screens/HomeWrapper.tsx:353`, `:373`, `:391`, `:400`; `src/app/components/BottomNav.tsx:120`; `src/app/components/NaverMapComponent.tsx:52`.

### 2. 밝은 테마의 보조 색상이 지나치게 연하다 — 높음

공지 날짜·설정 설명·홈 시간표 보조 문구에 `#94a3b8`을 사용한다. 흰색 배경과 계산한 대비는 약 2.56:1이다. 작은 글씨에 연한 색이 겹쳐 실제 화면에서 읽는 데 힘이 든다.

제안: 읽어야 하는 설명과 날짜는 `#64748b` 수준의 더 진한 색을 기본으로 삼고, 더 연한 회색은 장식·구분선·사용 불가 요소에 제한한다. 본문/보조/사용 불가 색상을 각각 의미에 맞춰 정의한다.

근거: `src/app/screens/NoticeWrapper.tsx`의 날짜; `src/app/screens/SettingsWrapper.tsx:299`; `src/app/screens/HomeWrapper.tsx:396`.

### 3. 다크 모드에서 일부 아이콘이 배경에 묻힌다 — 높음

실제 화면에서 통학 뒤로가기와 지도 확대·축소/위치 버튼의 아이콘이 어둡다. 통학 뒤로가기 SVG는 `stroke="#0F172A"`를 직접 지정하고, 지도 SVG는 `fill="#334155"` 또는 남색을 직접 지정한다. 버튼 배경만 다크 색으로 바뀌어 아이콘 색상과 맞지 않는다. `#0f172a`와 `#1c1c1e` 대비는 약 1.05:1, `#334155`와 `#1c1c1e`는 약 1.64:1이다.

다크 홈 시간표에는 밝은 외곽 테두리와 행 구분선이 눈에 강하게 들어온다. 설정의 화면 모드 선택 영역은 선택 배경과 주변 배경의 차이가 약하다. 이 두 항목은 시각적 위계 개선 대상이다.

제안: SVG는 `currentColor`와 테마의 아이콘 색상을 사용한다. 다크 배경/카드/선/선택 상태를 각각 정의하고 밝은 테마 색상을 단순 치환하는 방식을 줄인다.

근거: `src/app/screens/CommuterBusWrapper.tsx:168`; `src/app/components/NaverMapComponent.tsx:796`; `src/styles/globals.css:208` 이하.

### 4. 좁은 화면에서 문구가 어색하게 끊긴다 — 높음

320px 홈 화면의 시간표 헤더에서 “전체 시간표”가 두 줄로 갈라지고 “후문 셔틀은 전철 출발 10분 전”의 마지막 글자가 따로 내려간다. 온보딩 제목은 “확인하세요”가 “확인하 / 세요”로 분리된다. 요소가 화면 안에 있어도 읽는 흐름은 깨진다.

제안: 한국어 제목에 단어 단위 줄바꿈을 적용하고, 좁은 화면의 제목 크기·헤더 배열을 조정한다. 시간표 설명은 독립된 다음 줄로 내려 여유를 확보하고 “전체 시간표”는 줄바꿈 없이 배치한다. 글씨를 더 작게 만들어 공간을 맞추지 않는다.

근거: 320×568 실제 화면; `src/app/screens/HomeWrapper.tsx:366`; `src/app/screens/OnboardingWrapper.tsx`의 첫 제목.

## 디자인 체계를 정리할 문제

### 5. 폰트 설정이 분산되어 있다 — 중간

전역 body는 시스템 폰트이고 많은 화면 요소는 `Public Sans`를 직접 지정한다. 홈 섹션 제목의 실제 계산값은 시스템 폰트, 18px, 굵기 800이었다. 한글 폰트를 포함한 공통 폰트 목록이 명시되어 있지 않아 기기별 대체 폰트와 영문/한글 조합의 차이를 관리하기 어렵다.

제안: 한글·영문·숫자에 사용할 공통 폰트 목록을 한 곳에 선언한다. 본문 400~500, 기능/소제목 600, 제목 700을 기본으로 두고 800~900은 특별히 강조할 숫자 정도에 제한한다. 시간 숫자의 폭 정렬은 유지한다.

근거: `src/styles/fonts.css:1`; `src/styles/globals.css:198`; 화면별 `font-['Public_Sans']`; 홈 `font-extrabold`/`font-black`.

### 6. 굵은 글씨가 많아 중요한 정보가 덜 두드러진다 — 중간

홈 브랜드, 섹션 제목, 시간, 목적지, 바로가기, 전체보기까지 굵은 글씨를 사용한다. 모든 항목이 힘을 주고 있어 버스 이용 판단에 필요한 정보가 먼저 읽히지 않는다. 운행 중·운행 없음·위치 확인 중도 큰 남색 카드의 같은 강조 영역에 놓인다.

제안: “어디서 타는지 → 언제 오는지 → 현재 상태” 순서로 홈 위계를 정리한다. 주 정보는 큰 숫자/제목, 보조 정보는 보통 굵기, 이동 링크는 덜 강조한다. 위치 준비/사용 불가 상태도 재시도나 위치 없이 보기 등 다음 행동과 함께 설계한다. 이번 로컬 환경의 “위치 확인 중”은 위치 기능 장애로 확정하지 않았다.

근거: `src/app/screens/HomeWrapper.tsx:270`~`:304`, `:352`~`:441`; 홈 실제 화면.

### 7. 카드와 그림자 사용이 과밀하다 — 중간

홈 바로가기에는 테두리와 그림자, 시간표에는 테두리·그림자·색 배경·구분선이 겹친다. 설정은 모든 행을 별도의 카드로 감싸고 아이콘에도 배경을 둔다. 화면에 떠 있는 작은 상자가 많아 내용을 훑는 속도가 떨어진다.

제안: 일반 정보 카드는 얇은 테두리 또는 배경 차이로 구분하고, 그림자는 모달·바텀시트 등 떠 있는 요소에 집중한다. 설정은 환경설정 한 묶음과 기타 한 묶음 안에서 행을 구분하는 형태를 검토한다.

근거: `src/app/screens/HomeWrapper.tsx:339`, `:364`; `src/app/screens/SettingsWrapper.tsx:35`, `:287`.

### 8. 둥근 정도와 선택 상태가 통일되지 않았다 — 중간

입력창 8px, 로그인 버튼 12px, 공지 카드 16px, 필터는 완전한 캡슐, 설정 선택기는 6~9px, 하단 메뉴는 16px로 표현된다. 크기별 차이 자체는 문제없지만 선택 상태도 화면 모드는 흰색, 언어는 남색, 하단 메뉴는 연한 남색이라 규칙을 익히기 어렵다.

제안: 입력/작은 버튼, 일반 카드, 큰 패널의 둥근 정도를 3단계로 정의하고 적용한다. 분할 선택기끼리는 같은 선택 표현을 사용하며 탭·필터·버튼의 역할 차이는 의도적으로 구분한다.

근거: `src/app/screens/LoginWrapper.tsx:140`, `:186`; `src/app/screens/SettingsWrapper.tsx:366`, `:422`; `src/app/components/BottomNav.tsx:103`.

### 9. 색상이 상태의 중요도를 정확히 표현하지 않는다 — 중간

공지의 일반 카테고리는 초록, 새 공지는 빨강이다. 로컬 공지 목록에서 NEW가 반복되면 긴급한 목록처럼 느껴진다. 남색은 브랜드·위치·시간·바로가기·필터 등 다양한 역할에 쓰인다.

제안: 빨강은 위험/긴급/파괴적 행동, 초록은 정상 운행/성공, 남색은 브랜드/선택/주요 동작에 연결한다. NEW는 작은 점이나 옅은 배지로 표시하고 긴급도와 분리한다. 실제 운영 공지의 NEW 빈도는 별도 확인한다.

근거: `src/app/screens/NoticeWrapper.tsx`의 `CATEGORY_STYLES` 및 NEW 배지.

### 10. 아이콘·탐색 명칭이 화면 간 다르다 — 중간

홈과 하단 메뉴에 셔틀·통학·공지 접근이 반복된다. 하단의 “프로필”을 누르면 상단 제목은 “설정”이다. 셔틀과 통학 하단 아이콘은 모두 버스 형태여서 빠르게 구분하기 어렵다. Lucide 아이콘과 직접 작성한 SVG도 혼용된다. 여러 출입구를 두는 것 자체보다 역할과 이름이 겹치는 점이 문제다.

제안: “프로필/설정” 명칭과 화면 역할을 맞춘다. 하단 메뉴의 두 버스 기능은 다른 아이콘이나 더 명확한 표현으로 구분한다. 홈 바로가기는 하단 메뉴를 그대로 반복하기보다 자주 필요한 구체적 행동을 검토한다. 아이콘 크기·선 굵기·터치 영역도 공통화한다.

근거: `src/app/components/BottomNav.tsx`; `src/app/screens/HomeWrapper.tsx:339`; `src/app/screens/SettingsWrapper.tsx:206`.

### 11. 온보딩과 빈 상태에서 다음 행동이 약하다 — 중간

320px 온보딩 첫 화면은 제목·설명·400px 높이의 그래픽을 보여주며 “시작하기”는 아래 여러 섹션 뒤에 있다. 재방문하지 않은 사용자가 앱에 들어가기 위해 긴 화면을 내려야 한다. 통학 빈 상태도 “노선을 찾을 수 없습니다”와 “등교 노선이 없습니다”만 보여준다.

제안: 온보딩 첫 설명 바로 아래에 주요 시작 버튼을 제공한다. 빈 상태는 선택 필터 변경·시간표 확인·재시도 등 상황에 맞는 다음 행동을 제공하고, 조회 실패·등록 없음·운행 종료를 구분한다.

근거: 320×568 온보딩과 통학 빈 상태 실제 화면; `src/app/screens/OnboardingWrapper.tsx`; `src/app/screens/CommuterBusWrapper.tsx:496`.

## 추가 소스 검토 항목

- 통학 카드 내부에 10~12px 배지·상태·설명이 많고 노선 아이콘에도 큰 그림자가 있다. 실제 노선 데이터와 긴 정류장명으로 검증한 뒤 조정해야 한다.
- 지도 마커는 9px ETA와 11px 라벨, 최대 너비 100~122px를 사용한다. 긴 정류장명과 여러 차량이 겹치는 상황을 실제 지도에서 확인해야 한다.
- 문의 모달, 긴 공지 본문, 공지 이미지, 기사·관리자 화면은 이번 디자인 검토의 실제 조작 범위에 포함하지 않았다.

## 권장 수정 순서

1. 다크 아이콘과 보조 글씨 대비 수정.
2. 폰트·글씨 크기·굵기·줄 높이 기준 확정 및 공통화.
3. 320px 한국어 줄바꿈과 시간표 헤더 배치 수정.
4. 홈 정보 위계와 하단 메뉴 명칭/아이콘 정리.
5. 카드·선택기·그림자·색상 의미 통일.
6. 온보딩 첫 버튼과 빈 상태의 다음 행동 보강.

수정 후 동일한 320px/390px 화면과 밝은/다크 모드로 비교하고, 실기기 PWA에서 최종 확인한다.
