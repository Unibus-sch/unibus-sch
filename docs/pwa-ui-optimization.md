# PWA 모바일 화면 안정화 계획

## 목표와 작업 범위

작업 브랜치: `codex/pwa-ui-optimization`.
마이그레이션 작업공간에서 시작하며 원본 프로젝트·운영 배포·DNS·DB는 변경하지 않습니다.
현재 완료된 Spring 마이그레이션 커밋을 기반으로 하므로, 배포 브랜치 반영 시 UI 커밋과 백엔드 커밋 범위를 구분해야 합니다.

목표는 화면을 통째로 축소하는 것이 아니라 기기 화면 폭에 맞춰 배치하고,
헤더·하단 메뉴는 유지하면서 본문만 스크롤되도록 만드는 것입니다.
좁은 기기에서는 줄바꿈과 배치가 달라질 수 있지만 내용·버튼이 잘리면 안 됩니다.

## 코드에서 발견한 원인 후보

- `index.html`의 viewport가 `width=430`으로 고정되어 실제 기기 폭과 다름.
- `AnimatedMobileLayout`은 `h-dvh`, 별도 `MobileLayout`은 `h-screen`을 사용해 높이 기준이 다름.
- iOS 설치형 PWA CSS는 `100vh`와 하단 메뉴 `position:fixed`로 따로 전환함.
  모바일 브라우저·설치형 PWA가 다른 위치 기준을 사용하는 상태임.
- 홈·설정은 헤더를 포함하는 전체 화면 스크롤, 공지는 별도 본문 스크롤로 구성되어 동작이 다름.
- 일부 화면의 하단 여백이 `120px` 등 고정값이고 메뉴·홈 인디케이터 높이와 직접 연동되지 않음.
- 화면 전환 요소의 transform과 fixed 모달이 겹칠 때 위치 기준이 달라질 가능성이 있음.
- `src/imports`에는 디자인 출력용 고정 크기 코드가 있음. 실제 라우트에서 사용되는지 확인한 후 수정하며 일괄 교체하지 않음.

위 내용은 코드 조사 결과이며 특정 기기의 현상 재현·원인 확정은 아직 진행하지 않았습니다.

## 진행 단계

1. 화면 폭 정상화: `width=device-width, initial-scale=1, viewport-fit=cover` 적용.
   자동 회귀 검사와 타입 검사, 빌드부터 확인. 기존 430px 기준에서 가려졌던 좁은 화면 문제를 수집.
2. 공통 앱 셸 정리: 동적 화면 높이, 안전 영역, 하단 메뉴 영역을 한 곳에서 관리.
   셸을 `헤더 / min-height:0 본문 / 하단 메뉴` 형태로 구성하고 문서 전체 스크롤을 방지.
   앱 셸 내부 하단 메뉴에는 하나의 위치 기준만 사용하고 메뉴 실제 높이를 본문에서 확보.
   iOS 전용 우회 CSS는 실제 재현 결과에 따라 대체하며 확인 없이 제거하지 않음.
3. 화면별 적용: 홈·공지·설정부터 본문 스크롤을 통일하고, 통학 목록·시간표·지도·기사 화면으로 확장.
   지도의 이동·확대 제스처와 목록 스크롤은 분리. 지도 크기 변경 후 지도 SDK의 재계산도 확인.
4. 키보드·모달: 로그인·가입·문의 입력 중 마지막 필드와 제출 버튼에 접근 가능하게 함.
   필요한 경우 공통 VisualViewport 처리를 검토하되 pinch 확대 시 배치를 강제로 재설정하지 않음.
   모달은 변형된 화면 전환 부모와 분리하고, 모달 닫힘 후 본문 스크롤·포커스 복원을 검증.
5. 회귀 검증 후 체크포인트: 화면별로 작은 커밋을 만들고 프리뷰에서 검토한 뒤 스테이징에 반영.
   이번 작업 자체로 Vercel 배포나 운영 전환을 실행하지 않음.

## 확대·축소 정책

화면 잘림을 해결하기 위해 `user-scalable=no`, `maximum-scale=1` 또는 전역 터치 차단을 사용하지 않습니다.
사용자 확대 기능을 막으면 접근성이 저하되고 브라우저별로 동일하게 적용되지 않을 수 있습니다.
우선 초기 배율과 반응형 배치를 정상화하고, 작은 입력 글씨로 인한 자동 확대와 불필요한 두 번 탭 동작을 개별 검토합니다.
지도 자체 확대는 별도 기능이므로 유지합니다. 사용자가 확대 차단을 명시적으로 원하면 영향과 지원 범위를 설명한 후 결정합니다.

## 검증 기준

| 상황 | 확인 항목 |
|---|---|
| 320·360·375·390·412·430px 폭 | 가로 넘침 없음, 버튼·텍스트 접근 가능 |
| 낮은 화면·가로 회전 | 마지막 항목 접근 가능, 메뉴가 본문을 가리지 않음 |
| 본문 상단·중간·최하단 | 헤더·하단 메뉴 위치 유지, 의도하지 않은 문서 스크롤 없음 |
| iPhone Safari / 홈 화면 PWA | 노치·상태표시줄·홈 인디케이터에 내용 가림 없음 |
| Android Chrome / 설치형 PWA | 주소창 변화 후 높이 정상, 제스처 영역 가림 없음 |
| 키보드 열기·닫기 | 입력·제출 가능, 닫힌 뒤 화면 높이 복원 |
| 모달·시간표·지도 | 독립 스크롤, 닫힘 후 스크롤 복원, 지도 제스처 정상 |
| 글자 확대·페이지 확대 | 정보 손실 없이 탐색 가능 |
| 서비스워커 업데이트 | 새 레이아웃 버전 적용 확인, 오래된 화면과 혼동하지 않음 |

브라우저 크기 변경 검증은 실제 노치·키보드·설치형 iOS PWA 검증을 대체하지 않습니다.
최종 확인에는 사용자 휴대폰의 기종·OS·브라우저 버전과 설치형/브라우저 구분이 필요합니다.

## 현재 상태

새 브랜치 생성과 코드 조사, 화면 폭 정상화까지 진행했습니다.
공통 셸·화면별 스크롤 통일과 실제 기기 E2E는 다음 단계이며 아직 완료된 것으로 간주하지 않습니다.

참고: [MDN viewport](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/meta/name/viewport),
[안전 영역 CSS](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env).
