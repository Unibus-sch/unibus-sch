# PWA 화면 브라우저 검증 결과

검증일: 2026-10-05. 브랜치: `codex/pwa-ui-optimization`.

## 검증 환경

최신 로컬 소스를 Chrome에서 실행하고 브라우저 viewport 크기를 변경했습니다.
실제 iPhone 15·17, 모바일 Safari 또는 설치형 iOS PWA를 실행한 것은 아닙니다.
인증서·안전 영역·모바일 키보드·주소창 동작은 이번 환경으로 검증할 수 없습니다.
API 주소는 로컬 전용 검증 주소로 설정했고 원격 계정이나 DB는 사용하지 않았습니다.

## 확인한 결과

| 화면·크기 | 결과 | 근거 |
|---|---|---|
| 로그인 393×852 | 입력창·버튼 가로/하단 넘침 없음 | 문서 폭 393, 높이 852; 모든 입력창·버튼 경계 확인 |
| 로그인 402×874 | 입력창·버튼 가로/하단 넘침 없음 | 문서 폭 402; 경계 밖 입력창·버튼 0개 |
| 로그인 320×568 | 본문 스크롤로 마지막 버튼 접근 가능 | 내부 스크롤 높이 842, 표시 높이 568, 최하단 scrollTop 274 |
| 로그인 320×568 최하단 | 헤더 유지 목표 미충족 | “로그인” 헤더 top=-258.75, 회원가입 버튼 y=516~536 |

작은 화면에서 초기 화면 아래에 버튼이 있는 것은 스크롤로 접근할 수 있으므로 그 자체로 잘림 버그는 아닙니다.
하지만 헤더까지 같은 영역에서 스크롤되어 사라지는 것은 기획한 고정 헤더 동작과 다릅니다.
이번 검증은 첫 불일치 확인 후 중단했습니다. 회원가입 화면 진입까지 확인했지만 전체 검증은 하지 않았습니다.
홈·공지·설정·지도·기사 화면은 이번 브라우저 검증에서 확인하지 않았습니다.

## 다음 수정 대상

`src/app/screens/LoginWrapper.tsx`의 전체 화면 스크롤 안에 헤더가 포함되어 있습니다.
헤더를 스크롤 본문과 분리하고, 본문에 `flex:1; min-height:0; overflow-y:auto`를 적용하는 방식을 검토합니다.
다른 화면의 공통 셸 정리와 함께 적용하되 화면별 중첩 스크롤을 만들지 않도록 합니다.
수정 후 동일 크기에서 헤더 위치 유지와 마지막 버튼 접근을 다시 검증합니다.

## 별도로 남은 검증

- 로그인 후 홈·공지·설정의 스크롤 및 하단 메뉴 위치.
- 지도·시간표 모달·기사 운행 화면, 가로 회전과 글자 확대.
- 실제 iPhone의 Safari와 홈 화면 PWA에서 상태표시줄·홈 인디케이터·키보드.
- 설치된 PWA에 최신 서비스워커와 새 레이아웃이 적용되는지.

콘솔에서는 React 컴포넌트 안의 script 태그 관련 오류와 React Router v7 전환 경고도 관찰됐습니다.
이 메시지들이 화면 잘림의 직접 원인이라는 근거는 없으며 별도 확인 대상으로 남깁니다.

## 수정 후 재검증 — 2026-10-05

로그인 헤더·본문을 분리하고, 공통 셸에서 하단 메뉴의 실제 높이를 레이아웃 공간으로 확보했습니다.
홈·설정·공지·통학 화면의 메뉴 보정용 120px 여백과 셔틀의 104px 여백을 제거했습니다.
설치형 iOS만 메뉴를 fixed로 바꾸던 CSS 대신 공통 dvh 높이와 vh 대체값을 사용합니다.
작은 화면의 셔틀 안내 패널은 상단 제어 영역을 넘지 않도록 최대 높이를 제한했습니다.

검증은 `scripts/ui-fixture-server.mjs`의 로컬 전용 일반 사용자와 공지 25개로 진행했습니다.
UI에서 실제 로그인 버튼을 눌러 로컬 API 응답을 받고, 보호된 화면에 진입했습니다.
실제 Spring 인증·Supabase 연동 검증이 아니며 원격 데이터나 기존 세션은 사용하지 않았습니다.
fixture 서버는 127.0.0.1:4186에만 바인딩하고 허용된 로컬 프런트 외의 CORS 요청은 거부합니다.
공지를 포함한 데이터는 메모리에만 존재하며 쓰기 API는 로그인·로그아웃 외에 제공하지 않습니다.

| 확인 항목 | 결과 |
|---|---|
| 로그인 320×568 최하단 | 헤더 top=0 유지, 회원가입 버튼 y=516~536, 문서 scrollTop=0 |
| 홈 320×568 최하단 | 헤더 top=0, 메뉴 top=497 유지, 마지막 본문 버튼 bottom≈434 |
| 공지 320×568 최하단 | 25번째 공지 y=420~444, 메뉴 top=497, 본문 scrollTop=2625 |
| 설정 320×568 최하단 | 헤더 top=0, 로그아웃 버튼 bottom=449, 메뉴 top=497 |
| 공지 360×640 / 375×667 / 393×852 / 402×874 / 430×932 | 문서 가로 넘침 없음, 본문 끝=메뉴 시작, 메뉴 끝=화면 하단 |
| 공지 가로 852×393 | 데스크톱 미리보기 프레임 유지, 본문 끝=메뉴 시작, 메뉴가 화면 안에 존재 |

추가로 문의 모달과 하단 메뉴의 z-index가 같아 버튼이 가려질 가능성을 확인했습니다.
문의·공지 이미지 모달을 body portal의 z-index 100으로 분리했습니다.
문의 입력 필드도 16px로 통일했습니다. 문의 창 최하단 스크롤 후 제출 버튼 bottom≈548이며,
버튼 중앙의 실제 최상위 요소가 “문의 접수”임을 확인했습니다. 문의는 실제로 제출하지 않았습니다.
모달 닫힘 후 설정 스크롤·초점 복원과 공지 탭 이동도 확인했습니다.

스크린샷은 Git에서 제외되는 `backend/build/ui-verification/support-320.jpg`에 저장했습니다.
실제 iOS PWA·키보드·안전 영역, 실제 지도 SDK 및 기사 화면, 공지 이미지 모달의 전체 상호작용은 아직 검증하지 않았습니다.
React 가이드 검토 시 전역 resize 구독이나 React 상태 갱신을 추가하지 않고 CSS 구조로 메뉴 높이를 처리했습니다.

모바일 구조 회귀 테스트 3개와 API 연결 회귀 테스트 1개, TypeScript 검사, 변경 TSX의 ESLint 검사,
Vite/PWA 빌드가 통과했습니다. 구조 테스트는 정적 코드 계약 검사이며 실제 브라우저 검증을 대체하지 않습니다.
검증 서버는 종료했습니다. 종료 시 로컬 사용자 로그아웃 확인창에서 브라우저 자동화가 응답하지 않아
로그아웃 완료·브라우저 크기 복원은 확인하지 못했습니다. 남아 있는 창이 있다면 사용자 확인 후 닫으면 됩니다.
해당 계정·토큰은 DB 없는 로컬 테스트용 값이며 원격 계정과 무관합니다.
